# C++ 图书管理系统

一个基于 C++17 开发的命令行图书管理系统，支持图书信息添加、查询、删除、修改，以及图书数据的本地文件存储。

本项目主要用于学习 C++ 面向对象编程、多文件项目组织、文件读写、CMake 构建和 Git 版本管理。

## 项目功能

- 添加图书信息
- 展示所有图书
- 根据图书信息查询
- 删除图书
- 修改图书信息
- 将图书数据保存到本地文件
- 从本地文件加载图书数据

## 技术栈
- **编程语言：** C++17
- **标准库：** STL
- **文件存储：** C++ 文件流（fstream）
- **构建工具：** CMake
- **版本控制：** Git
- **开发环境：** Visual Studio 2022、Ubuntu Linux

## 编译与运行

### Linux 环境

确保已安装 CMake 和 G++ 编译器

1. 进入项目目录：

```bash
cd 图书管理系统
```

2. 生成构建文件：

```bash
cmake -S . -B build
```

3. 编译项目：

```bash
cmake --build build
```

4. 运行程序：

```bash
./build/BookManager
```

### Windows 环境

本项目也可以使用 Visual Studio 2022 打开解决方案进行编译和运行。

1. 在仓库根目录打开'图书管理系统.sln'。
2. 选择 Debug 或 Release 配置。
3. 点击生成解决方案。
4. 运行程序。

## 数据存储

项目使用‘book.txt’ 文本文件保存图书数据。

每本图书占用 5 行，按照以下顺序存储：

1. 图书名称
2. 作者
3. 图书编号
4. 图书价格
5. 库存数量

数据采用逐行读取和写入的方式进行管理。

程序加载数据时会进行基本的数据合法性检查，包括：
- 价格和库存数量的格式检查
- 价格和库存数量不能为负数
- 图书名称、作者和编号不能为空
- 避免重复的图书编号
- 兼容 Windows CRLF 换行符

## 开发过程中遇到的问题

### Windows 与 Linux 换行符兼容问题

**问题：**

在 Windows 环境下保存的图书数据文件，在 Linux 环境下读取时出现数据加载异常。

**原因：**

Windows 和 Linux 使用的文本换行符不同。Windows 通常使用 CRLF（`\r\n`），Linux 通常使用 LF（`\n`）。

使用 `std::getline()` 读取时，Windows 文件末尾的 `\r` 可能被保留下来，影响后续数据解析。

**解决方案：**

编写 `RemoveCR()` 函数，在数据解析前清理字符串末尾的 `\r`，保证 Windows 和 Linux 环境下的数据读取兼容。
